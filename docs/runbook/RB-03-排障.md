# RB-03 排障

## 先看三处

| 现象 | 先看 | 常见原因 |
|---|---|---|
| 看板无数据 | `make ps` 容器状态 | db 没 healthy，ingest 起不来 |
| 数据断一段 | 补传水位线（`/healthz`） | 断网、spool 满、幂等冲突 |
| 曲线卡顿 | 浏览器 Performance | 窗口太长，没走聚合/LTTB |
| 时间不对 | 容器时区、设备时钟 | 时钟偏移（PoC 只记录不校正） |

## 日志（JSON，一行一条）

```bash
docker logs --tail 50 interroll-poc-ingest-1 | jq -r '"\\(.ts) \\(.level) \\(.msg)"'
docker logs interroll-poc-api-1 2>&1 | grep '"level": "error"'
```

字段：`ts / level / svc / msg`，必要时带 `zone / drive / trace_id / rows / spool / detail`。

- 全量上限：每个容器 `10m × 3`（compose 里 `x-logging`），不会写满边缘机磁盘；
- 崩溃栈：进程启用了 `faulthandler`，段错误/死锁会把栈打到 stderr，`docker logs` 里能看到。

## 事件表（不是日志流水，是"发生了什么"）

```sql
select ts, kind, severity, detail from events order by ts desc limit 20;
```

当前会记：`ingest_start` / `ingest_stop` / `db_recovered` / `spool_replayed`。
一天几十条，适合做审计与时间线；`make diag` 会导出最近 200 条为 `events.ndjson`。

## 退出码怎么读

```bash
docker ps -a --filter name=interroll-poc --format '{{.Names}}\t{{.Status}}'
```

| 退出码 | 含义 | 首查 |
|---|---|---|
| 0 | 正常退出 | —— |
| 1 | 应用异常 | 日志里的 traceback |
| **137** | SIGKILL（常见 **OOM**） | `docker inspect --format '{{.State.OOMKilled}}'` |
| 143 | SIGTERM（`docker stop`） | 正常停栈；ingest 会先 flush 再退 |

## 健康检查

`mqtt` / `db` / `api` / `ingest` 都有 healthcheck（15s 一次）。
容器"假死"时 compose 会自动重启——之前只有 mqtt/db 有，api 挂死不重启。

## 命令

```bash
make logs                 # 全栈日志
docker compose -f deploy/compose/compose.yaml logs ingest --tail=200
docker compose -f deploy/compose/compose.yaml exec db psql -U poc -d poc -c '\dt+'
```

## 诊断包

```bash
make diag     # → dist/interroll-diag-<ts>.zip
```

包含：`system.txt`（含退出码）、`config/`（脱敏）、`logs/`（每容器 300 行）、
`mqtt-tail.ndjson`（最近 10 条）、`db-stats.txt`、`events.ndjson`（最近 200 条）、
`mqtt-sys.txt`（连接数/峰值/速率/丢弃，现场判断"是不是设备在抖"的第一手证据）。
