# 需求说明（v1，待确认）

> 这份文档定「做什么、做到什么算完」；WBS 定「怎么拆、多久」。
> 需求一句话：**在一台工控机上，把产线数据跑到看板上，并且断网、回滚、移交三件事都拿得出手。**

## 一、背景与约束

| 项 | 事实 |
|---|---|
| 场景 | 英特诺（Interroll）Python 全栈岗面试，48 小时准备期 |
| 岗位 JD 四件事 | React + Python + MQTT + TimescaleDB，外加容器化现场部署 |
| 可用时间 | 11-20 晚 3h、11-21 全天 8h、11-22 上午 4h（约 15h） |
| 硬件 | 本机 192.168.1.200，Docker 29；现场演示也在这台上 |
| 已有资产 | `docs/design/`（四屏设计稿）、`docs/adr/`（5 条决策）、48h 准备计划（vault） |

**约束**：vault 不动（后期只把 `docs/` 挂进 `git-docs/`）；宿主机 1883/5432/8000/5173 已被占，PoC 用 1884/5433/8001/5174。

## 二、目标（三条，都可当场验证）

1. **一条命令起得来**：`make up` 后 90 秒内看板出曲线，`make verify` 全绿。
2. **断网不丢数**：断 60 秒，恢复后曲线补齐，`待补条数` 回到 0。
3. **可移交**：`make diag` 出 zip、`make rollback` 30 秒回上一版，两者都能当场做。

## 六、非功能需求

| 项 | 指标 | 怎么验 |
|---|---|---|
| 资源 | 4C / 8G 内跑满五容器 | `docker stats` |
| 启动 | 冷启动到出数 ≤ 90s | 计时 |
| 离线 | 无外网也能起（镜像已落地） | 断网 `make up` |
| 日志 | 结构化 JSON，不落密码 | `make diag` 抽检 |
| 数据 | 原始点留 7 天、聚合留 90 天 | `init.sql` 保留策略 |

## 七、总验收：演示六步

1. `make up` → 看板出曲线；
2. 指出 Z6 离线但数据不丢；
3. `make demo-offline` → 断 60s → 恢复自动补齐；
4. 切 1h 窗口，曲线不卡（走聚合）；
5. `make diag` → 讲诊断包含什么；
6. `make rollback` → 30 秒回上一版。

六步全过 = 需求达成。缺一步就不算「可移交」。

## 八、假设、风险与待确认

**假设**：面试现场有网但可以断；演示在本机，不在客户现场；不接真 PLC。

| 风险 | 影响 | 对策 |
|---|---|---|
| 时间不够（15h vs 需求） | 砍 P1 | WBS 里标了 P0/P1，P0 线是可演示下限 |
| 镜像拉不动 | 起不来 | 国内镜像源；提前 `docker save` 备份 tar |
| 断网补传做不干净 | 讲不透 | 先做「不丢」再做「不重」，幂等键最小实现 |
| 演示机端口冲突 | 起不来 | 全端口走 `.env`，README 有对照表 |

**待确认**：① 是否要多机形态（现在只单机）② 告警阈值要不要可配 ③ 移动端是否进 P0。
