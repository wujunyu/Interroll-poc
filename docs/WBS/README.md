## 二、产能对账（这是这份 WBS 最该看的一行）

| 项 | 数值 |
|---|---|
| 可用时间 | 11-20 晚 3h + 11-21 8h + 11-22 上午 4h ≈ **15h ≈ 36🍅** |
| P0 需求 | **62🍅 ≈ 25h** |
| 缺口 | **-22🍅（约 8.8 小时）** |

**结论：按当前需求，P0 也做不完。** 必须先砍，三档砍法任选：

| 砍法 | 砍掉 | 省 | 代价 |
|---|---|---|---|
| A（推荐） | P5-3 诊断页 → 只留 P0 两屏；P4-2 WS 改 2s 轮询 | 6🍅 | 「可移交」少一个可视化证据，但 `make diag` 还在 |

砍完 A 后 ≈ 43🍅 ≈ 17.2h，**仍比可用 15h 多 2.2 小时**——得再砍 B 或 C，或者把 P5 的诊断页放到面试后。

## 三、依赖顺序

```
P1 ✅ ──> P2 ──> P3 ──> P4 ──> P5 ──> P8
            │        └──> P6 ──┘
            └──> P7 ──────────┘
```

- P4 只依赖 P2（不必等 P3），可与 P3 并行；
- P7 只依赖 P2（代码跑通就能写卡），可插空做；
- P8 必须最后，其余任意阶段没完成都不许进 P8。

## 四、怎么用

- 在 vault 建索引页（`git-docs/WBS` 挂载后）：

```dataviewjs
await dv.view("scripts/project-wbs/task-tree", { scanPath: "git-docs/WBS" });
```

- 状态约定：`- [ ]` 未开始 → `- [x] … ✅` 完成，同时把该阶段的 `**实际**` 回填真实番茄数。
- **估时是承诺，不是愿望**：实际超过预估 50% 的任务，在阶段文件里补一行「为什么估错」。
- 每周（或每阶段结束）回填一次；不回填的 WBS 三天后就没人看。

## 五、自检（改完 WBS 必跑）

```bash
grep -ohE '\[ID:: [^]]+\]' docs/WBS/*.md | sort | uniq -d          # 应为空
grep -nE '^- \[[ x]\]' docs/WBS/*.md | grep -v 'EST::'             # 应为空
head -1 docs/WBS/P*.md | grep -c '\*\*目标\*\*'                     # 应为 8
grep -c 'TODO' docs/WBS/*.md                                        # 0 为干净
```
