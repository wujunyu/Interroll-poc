# ADR-0001 单机五容器，而不是微服务

- **状态**：已接受
- **日期**：2026-11-20

## 背景

现场是**客户的一台工控机/笔记本**，装机的是集成商，不是我们的运维。团队规模 1 人（演示），
要覆盖采集、存储、接口、展示四段。可选：①单体进程 ②单机多容器 ③K8s。

## 决策

单机 5 个容器（mqtt / db / ingest / api / web），用 compose 编排，现场交付时换 Podman quadlet。

## 代价

- 多一层网络与资源配置，调试要跨容器看日志；
- 容器间要靠约定（端口、DSN）而不是函数调用，接口变更更贵；
- 单机没有真正的横向扩展能力。

## 替代方案

| 方案 | 为什么没选 |
|---|---|
| 单体进程 | 一段崩全崩；DB 与 Broker 还是要独立进程，省不了多少 |
| K8s | 一台机器上跑控制面纯亏；集成商不会维护 etcd |
| Serverless | 现场常常断网，且需要常驻 MQTT 连接 |
