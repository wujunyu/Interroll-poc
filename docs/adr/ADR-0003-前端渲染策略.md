# ADR-0003 看板渲染：LTTB + 节流，不换 uPlot

- **状态**：已接受
- **日期**：2026-11-20

## 背景

10Hz 实时曲线，窗口 60s = 600 点/序列，6 条序列 = 3,600 点。若窗口拉到 1 小时，
原始点 36,000/序列，ECharts 直绘会掉帧。

## 决策

- 原始窗口 ≤ 5 分钟（≤ 3,000 点）直绘；
- 更长的窗口先**降频**：查 `telemetry_1m` 连续聚合（1 小时 = 60 点；7 天 = 10,080 点）；
- 降频后仍超过 1,000 点（如 7 天）才做 **LTTB 抽样**（Largest-Triangle-Three-Buckets，保形不保统计），目标 ≤ 1,000 点/序列；
- 两类手段分工：**聚合负责降频，LTTB 负责降到像素级且不丢峰谷**；
- LTTB 的输出**只用于画线**；平均值、最大值、告警判定一律查聚合表或原始表，不许拿抽样点算。
- WS 推送**节流到 10fps**（渲染 60fps，数据 10Hz 已经足够）；
- 百万点场景才考虑换 uPlot——PoC 不换。

## 代价

- 抽样会丢峰值细节（LTTB 保留趋势，不保精度）；
- 节流意味着「看到的数据最多晚 100ms」；
- 两套渲染路径（直绘 / 抽样）要分别测。

## 替代方案

| 方案 | 为什么没选 |
|---|---|
| 全量直绘 | 1 小时窗口必卡 |
| Canvas 手写渲染 | 工期不够，收益在本量级不明显 |
| 服务端渲染图片 | 交互全丢 |
