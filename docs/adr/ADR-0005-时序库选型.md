# ADR-0005 选 TimescaleDB，不选 InfluxDB

- **状态**：已接受
- **日期**：2026-11-20

## 背景

需要存高频点位、做时间桶聚合、设置保留与压缩；团队既有经验在 SQL Server（关系型、存储过程、执行计划）。
现场还可能要求离线部署与备份还原。

## 决策

TimescaleDB（PG 17 扩展）。

## 代价

- 写入吞吐不如专用 TSDB，压缩策略要自己调；
- 依赖 PostgreSQL 运维知识（VACUUM、连接数、WAL）；
- 单机版没有原生集群，要主备得自己搭。

## 替代方案

| 方案 | 为什么没选 |
|---|---|
| InfluxDB | 专有查询语言（Flux/InfluxQL），SQL 经验迁移不过去；备份/恢复更别扭 |
| 纯 PG 分区表 | 连续聚合、保留策略、压缩都要自己写，工期不够 |
| Prometheus | 面向指标不面向设备时序，长保留很贵 |
