# ADR-0002 回传靠聚合，补传靠水位线

- **状态**：已接受
- **日期**：2026-11-20

## 背景

36 驱动 × 10Hz = 360 点/秒，原始行一天约 3,100 万条。若按原始点全量回传中心，
带宽与存储都不可接受（按 52GB/天量级估算）。同时现场断网是常态，不能假设链路可靠。

## 决策

1. 边缘**先落本地**，中心只收**聚合结果**（1 分钟桶 + 必要的原始点抽样）；
2. 补传以 `device_id + ts + seq` 为**幂等键**，重复到达不重复写；
3. 用**水位线**（已确认写入的最大 ts）表达「补到哪了」，而不是「补了多少条」。

## 代价

- 中心看不到秒级原始波形，只能看聚合 + 抽样；
- 幂等键要求设备侧有稳定 seq，时钟偏移要单独处理；
- 水位线要持久化，多实例会打架（PoC 只跑单实例）。

## 替代方案

| 方案 | 为什么没选 |
|---|---|
| 全量原始点回传 | 带宽与存储成本高一个数量级 |
| 只传变化（死区压缩） | 曲线会失真，且实现复杂度高 |
| 中心拉取而不是边缘推送 | 现场 NAT/防火墙下更难打通 |
