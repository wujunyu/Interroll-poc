**主张**：断网恢复后**一次性全速补传**会丢数据，反而比断网时丢得更多；补传必须限速。
**原文**：2880 条欠账在 0.1 秒内喷完，落库 7134/7200，差 66 条；限速 400 条/秒后 7200/7200。
**边界**：Broker 逐客户端队列有上限（mosquitto 默认 1000 条），订阅端消费不过来就丢。
适用于任何「积压后集中回放」的场景（不只是 MQTT）。
**冲突/反例**：如果订阅端消费能力远高于补传速率，全速也不会丢；但那是运气，不是设计。
