**主张**：小数据量下 hypertable **不比普通表快**（甚至略慢），它的价值在「按时间淘汰 + 压缩 + 索引规模」，不在查询。

**实测**（同一份 2,000,000 行、338 MB 数据，本机）：

| 测试 | 普通表 + ts 索引 | hypertable（10 分钟 chunk）|
|---|---|---|
| 5 分钟窗口 `count(*)` | **8.4 ms** | 11.3 ms（规划开销）|
| 删除 30 分钟数据（64.7 万行）| DELETE 254 ms，表仍 338 MB | `drop_chunks` **11 ms**，降到 324 MB |
| 压缩 | 无 | **35 MB → 5.8 MB（约 6×）** |
| 唯一约束 | 全表 | **每 chunk 内**（PK 必须含时间列）|

**边界**：1e7 行以内两者查询性能基本持平；差异在 1e8 行以上（单索引过大、vacuum 跟不上）或需要长期保留/压缩时才显著。

**反例**：如果只做点查和短期范围查、从不删旧数据，普通表 + 时间索引完全够用，不必上 hypertable。
