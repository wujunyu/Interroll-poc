**主张**：补传缓冲用 NDJSON，读取靠文件对象自身做游标；不记偏移，重复由主键挡掉。
**原文**：200,000 行 / 15.7MB 补传，峰值 RSS 40MB，与文件大小无关；14.9s 落库全中。
**边界**：`for line in fh` 是流式；把文件读成 list 才是 OOM 的来源（第一版就是）。
崩溃留下的半行必须 try/except 跳过，否则一行坏掉整批失败。
**冲突/反例**：需要「精确一次消费 + 随机查询」时，NDJSON 不如 SQLite/嵌入式队列；PoC 只做顺序补传。
