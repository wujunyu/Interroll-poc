# 知识库契约（改结构前先改这里）

> 四层：**源 → 卡 → 图 → 稿**。每一层解决一类问题，越往下越短。
> 位置：`docs/kb/`。挂进 Obsidian 后（`RB-04`）可双链、可 Dataview。

## 一、四层

| 层 | 目录 | 回答什么 | 谁写 | 长度 |
|---|---|---|---|---|
| 源 | `0-源/SRC-YYYYMMDD-<slug>.md` | 原话/原文到底怎么说的 | 人贴原文，AI 可整理 | ≤ 10 行引用 |
| 卡 | `1-卡/C-<域>-<三位>.md` | 一条可独立引用的事实 | AI 起草，人过目 | ≤ 15 行 |
| 图 | `2-图/MOC-<主题>.md` | 这一块的整体判断与选型 | 人确认后写 | 一页 |
| 稿 | `3-稿/OUT-<场景>-v<N>.md` | 那 60 秒到底说什么 | 人 | 半页 |

## 二、硬规则

1. **一处事实只有一个地方**：`0-源` 存引用与出处，不整段复制 vault 原文。
2. **卡必须有 source**：没有出处的卡不能进 `2-图`。
3. **可信度四档**：`原文事实` / `原文观点` / `我的推断` / `待确认`。`3-稿` 只允许引用前两档。
4. **冲突不覆盖**：两条卡矛盾时新建 `C-<域>-<三位>-CONFLICT.md`，两边都留着。
5. **ID 不复用**：卡按域递增编号，删了也不回收。
6. **命名**：前缀 `SRC- / C- / MOC- / OUT-`，文件名全局唯一，不出现 `README.md`。

## 三、卡的形状

```markdown
---
type: 事实卡
id: C-RENDER-002
confidence: 原文事实        # 原文事实 | 原文观点 | 我的推断 | 待确认
source: "[[SRC-20261120-数据量与前端渲染]]"
verified: 2026-11-20
tags: [英特诺, PoC, 渲染]
---
**主张**：ECharts 在 10Hz 曲线下的瓶颈是「点数 = 频率 × 窗口」，不是帧率。
**原文**：「ECharts能抗得住10hz曲线吗？我记得之前是有点数限制。」
**边界**：窗口 60s ≈ 600 点/序列可直绘；再长走 LTTB 或换 uPlot。
**冲突/反例**：待确认（未实测百万点）。
```

## 四、AI 的写入边界

| 层 | AI 能写 | 不能写 |
|---|---|---|
| `0-源` | 摘要 + 出处 | 改写原话 |
| `1-卡` | 草案（带 `status: draft`） | 标成 `原文事实` 的推断 |
| `2-图` | 建议稿，提交人审 | 直接改已确认的图 |
| `3-稿` | 不写 | 不写 |

分支约定：AI 的卡走 `kb/<主题>` 分支，人 review 后合进 `main`。

## 五、自检

```bash
grep -L '^source:' docs/kb/1-卡/*.md   # 应为空
grep -oE 'id: C-[A-Z]+-[0-9]{3}' -r docs/kb/1-卡 | sort | uniq -d   # 应为空
```
